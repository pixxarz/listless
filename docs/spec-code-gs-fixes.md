# ผลการตรวจสอบข้อมูลเก็บที่ไหน และต้อง deploy อะไรบ้าง

> เอกสารนี้สำหรับคนที่ดูแล Google Apps Script ของโปรเจกต์นี้
> ระบบตรวจสอบข้อมูล (ชื่อ / ห้อง / วิชา) **เก็บผลการตัดสินไว้ในชีตแล้ว** ตั้งแต่เวอร์ชัน 1.3.0
> ทุกเครื่องที่เปิดหน้ารายงานจึงเห็นตรงกัน และไม่หายแม้ล้างเบราว์เซอร์

---

## 🚨 แก้โค้ดอย่างเดียวไม่พอ ต้อง Deploy ด้วย

นี่คือสาเหตุที่ **กดแก้ชื่อแล้วไม่มีอะไรขึ้นในชีต** ทั้งที่โค้ดถูกแล้ว

Apps Script → เมนู **Deploy** → **Manage deployments** → กดรูป **ดินสอ** → ช่อง Version เลือก **New version** → **Deploy**

ลิงก์ (`SHEET_URL`) จะไม่เปลี่ยน หน้าเว็บเดิมใช้ได้ต่อทันที
กด **Run** ในหน้า Apps Script ไม่นับเป็นการ deploy — เว็บยังคุยกับเวอร์ชันเดิมอยู่

หน้าเว็บรู้ตัวเองว่ายังไม่ได้ deploy: ถ้า `doGet` ตอบกลับมาโดยไม่มีช่อง `fixes`
แผงตรวจสอบข้อมูลจะขึ้นแถบแดงบอกว่ายังบันทึกลงชีตไม่ได้ และเก็บผลไว้ในเครื่องรอส่งให้แทน

## แผ่น `แก้ข้อมูล` — 8 คอลัมน์

`getFixSheet_()` สร้างให้อัตโนมัติพร้อมหัวตารางตอนใช้ครั้งแรก ไม่ต้องสร้างมือ

| คอลัมน์ | ชื่อหัวตาราง | เก็บอะไร | ตัวอย่าง |
|---|---|---|---|
| A | `id` | รหัสประจำรายการ (ระบบสร้างเอง ห้ามแก้มือ) | `room:สาทิดาทานะบัด` |
| B | `ชนิด` | `name` / `teacher` / `room` / `subject` | `room` |
| C | `การกระทำ` | `merge` = แก้ให้เหมือนกัน · `ignore` = ไม่ต้องแก้ | `merge` |
| D | `ค่าที่ใช้` | ค่าที่ถูกต้อง (ถ้าเป็นวิชาจะเป็นข้อความ JSON) | `ม.6/4` |
| E | `สมาชิก` | ค่าเดิมทั้งหมดที่ถูกรวม คั่นด้วย `\|\|` | `ม.6/3\|\|ม.6/4` |
| F | `หัวข้อ` | ชื่อที่แสดงในหน้าจอ | `สุพัตรา เปรยรัตน์` |
| G | `ผู้ตรวจ` | ชื่อคนที่กดยืนยัน | `ครูพิยะวุฒิ` |
| H | `เวลา` | เวลาที่กด (ประทับฝั่งเซิร์ฟเวอร์) | `2026-08-10T09:15:00.000Z` |

## คำสั่งที่หลังบ้านรับ

| คำสั่ง | วิธีเรียก | ทำอะไร |
|---|---|---|
| `action=fixes` | GET (JSONP) + `key` | คืนรายการทั้งหมดในแผ่น `แก้ข้อมูล` |
| ไม่ระบุ action | GET (JSONP) + `key` | คืน `rows` (ข้อมูลรายงาน) **พร้อม `fixes` ในคำตอบเดียวกัน** หน้าเว็บจึงไม่ต้องยิงถาม 2 รอบ |
| `action=savefix` | POST (`no-cors`) | บันทึก/ทับ/ลบ 1 รายการ |

ทั้งขาอ่านและขาเขียน **บังคับใส่รหัสผ่าน** เพราะในแผ่นมีชื่อนักเรียนและชื่อครู

### รูปแบบ payload ของ `savefix`

```json
{ "action": "savefix", "key": "รหัสผ่าน",
  "fix": { "id": "...", "type": "name", "action": "merge",
           "value": "ฉัตรชนก บัวศรี", "members": ["..."], "title": "...", "by": "ครูพิยะวุฒิ" } }
```

🚨 **ตัวรายการต้องอยู่ใน `fix` ห้ามวางไว้ระดับบนสุด** — ทั้ง 2 ชั้นมีช่องชื่อ `action` เหมือนกัน
ชั้นนอกคือชนิดคำสั่ง (`savefix`) ชั้นในคือผลการตัดสิน (`merge` / `ignore`)
ถ้าอ่านจากชั้นนอกตรงๆ ช่อง "การกระทำ" ในชีตจะกลายเป็นคำว่า `savefix` ทุกแถว

ยกเลิกการตัดสิน = ส่ง `"fix": { "id": "...", "remove": true }` (ลบอย่างเดียว ไม่เขียนกลับ)

🚨 **ค่าของวิชาเป็น object** (`{name, code}`) เพราะต้องเก็บชื่อกับรหัสคู่กัน
`fixValueOut_()` แปลงเป็นข้อความ JSON ก่อนเขียน และ `fixValueIn_()` แปลงกลับตอนอ่าน
ถ้าเขียนลงไปตรงๆ จะได้คำว่า `[object Object]` แล้วหน้าเว็บอ่านกลับมาใช้ไม่ได้

## ฝั่งหน้าเว็บทำงานยังไง (`js/fixes.js`)

ส่งขึ้น Apps Script ต้องใช้ `no-cors` ซึ่ง **อ่านคำตอบไม่ได้เลย** ยิงไปแล้วจึงไม่มีทางรู้จาก `fetch` ว่าถึงชีตจริงไหม
(บั๊กเดียวกับที่หน้ากรอกเคยเจอ จึงใช้ท่าเดียวกัน — ส่งแล้ว **อ่านกลับไปยืนยัน**)

เก็บ 3 ชั้น
- `serverList` — สิ่งที่อยู่ในชีตจริง มาจาก `doGet` ตอนโหลดและตอนเช็ครายงานใหม่ทุก 45 วิ
- `queue` — รายการที่กดแล้วแต่ยังยืนยันไม่ได้ว่าถึงชีต เก็บลง `localStorage` ด้วย ปิดหน้าไปแล้วเปิดใหม่ก็ยังส่งต่อให้
- `decisions` — `serverList` ทับด้วย `queue` = สิ่งที่หน้าจอเห็น กดแล้วเห็นผลทันทีไม่ต้องรอเน็ต

หลังส่ง จะอ่าน `action=fixes` กลับมาเทียบ **ทั้ง id และค่า** ตรงแล้วจึงตัดออกจากคิว
ยังไม่ตรงจะลองอ่านซ้ำอีก 2 รอบ (1.5 วิ แล้ว 3 วิ) ถ้ายังไม่ได้จะขึ้นแถบแดงพร้อมปุ่ม **ลองส่งอีกครั้ง**
ผลการตัดสินไม่หายไปไหน และไม่มีทางที่หน้าจอจะบอกว่าบันทึกแล้วทั้งที่ยังไม่ถึงชีต

ผลการตัดสินที่ค้างอยู่ในที่เก็บเดิม (`chanu_data_fixes_v1` ของเวอร์ชัน 1.2.0) จะถูกย้ายเข้าคิวและส่งขึ้นชีตให้อัตโนมัติครั้งแรกที่เปิดหน้ารายงาน

## ทดสอบว่าใช้ได้

เปิดลิงก์นี้ในเบราว์เซอร์ (แทน `รหัสผ่าน` ด้วยรหัสจริงของหน้ารายงาน)

```
<SHEET_URL>?action=fixes&key=รหัสผ่าน&callback=cb
```

| ผลลัพธ์ที่ได้ | แปลว่า |
|---|---|
| `cb({"result":"OK","fixes":[]});` | ใช้ได้แล้ว |
| `cb({"error":"unauthorized"});` | รหัสผ่านไม่ตรง |
| `cb({"error":"server"});` | โค้ดมีปัญหา ให้ดูใน Executions |
| ไม่มีช่อง `fixes` เลย | **ยังไม่ได้ deploy เวอร์ชันใหม่** |

---

## หมายเหตุความปลอดภัย

- แผ่น `แก้ข้อมูล` มีชื่อนักเรียนและชื่อครูอยู่ จึง **บังคับใส่รหัสผ่านทั้งตอนอ่านและตอนบันทึก**
- ระบบไม่ได้แก้ข้อมูลในแผ่น `รายงาน` เลย ใบต้นฉบับและเอกสารที่ปริ้นไปแล้วยังเป็นค่าเดิมทุกตัวอักษร
- ผลการตัดสินเป็นแค่ "ชั้นทับ" ที่หน้ารายงานเอาไปใช้ตอนแสดงผล ยกเลิกเมื่อไหร่ข้อมูลก็กลับเป็นเดิมทันที
