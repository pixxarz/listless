> ต่อจาก v1.4.2 ที่ใส่ระบบลองใหม่ไปแล้วแต่ยังไม่พอ

---

## ทำไมยังไม่จบใน v1.4.2

v1.4.2 ใส่การลองใหม่ 3 ครั้งต่อการกด 1 ที แต่วัดผลจริงบนเครื่องผู้ใช้แล้วยังใช้งานไม่ได้

- **Safari (iPhone)** — กด 7 ครั้ง เข้าได้ 2 ครั้ง (ทั้งที่แต่ละครั้งลองให้ 3 รอบแล้ว = ยิงไป 21 ครั้ง สำเร็จ 2)
- **Edge** — ต้องกดราว 8 ครั้งถึงเข้าได้

โอกาสสำเร็จต่อการยิง 1 ครั้งเหลือราว **10%** เท่านั้น

**สรุป: การลองใหม่เป็นการกลบอาการ ไม่ได้แก้ต้นเหตุ** ต้นเหตุคือเบราว์เซอร์แปลชื่อ `script.google.com` เป็นที่อยู่ไม่ได้ (`ERR_NAME_NOT_RESOLVED`) เพราะ Edge/Safari ใช้ตัวแปลชื่อโดเมนของตัวเอง ไม่ใช่ของเครื่อง

## ทางแก้ที่ต้นเหตุ — ทางผ่าน (proxy)

**ทำให้เบราว์เซอร์ไม่ต้องแปลชื่อของ Google อีกเลย**

เว็บเรียก `/gs` ซึ่งเป็นชื่อเว็บตัวเอง (เปิดได้อยู่แล้วแน่นอน) แล้ว Netlify ส่งต่อคำขอไปให้ Apps Script

```
/gs   https://script.google.com/macros/s/.../exec   200
```

🚨 **ต้องเป็นรหัส 200 เท่านั้น** ถ้าใช้ 301/302 เบราว์เซอร์จะวิ่งไป `script.google.com` เองอยู่ดี แล้วเจอปัญหาเดิม

### ทางถอยอัตโนมัติ — สำคัญที่สุดของงานรอบนี้

ไม่ใช่แค่เปลี่ยนที่อยู่แล้วจบ เพราะถ้าทางผ่านใช้ไม่ได้ (เช่นเปิดไฟล์จากเครื่องตรง ๆ ที่ไม่มี Netlify) จะพังทั้งระบบ

- ตั้งต้นใช้ `/gs` เสมอ
- ล้มด้วยความผิดพลาดของเครือข่าย → `markRouteFailed()` สลับไปยิง `script.google.com` ตรง ๆ **แล้วลองใหม่ทันที ไม่นับเป็นการลองซ้ำ** (เป็นการเปลี่ยนเส้นทาง ไม่ใช่เน็ตสะดุด)
- จำไว้ว่าทางไหนใช้ได้ ครั้งต่อไปใช้ทางนั้นเลย

**จึงไม่มีทางแย่กว่าเดิม** กรณีแย่สุดคือเท่าเดิม (ยิงตรง + ลองใหม่ 3 ครั้งแบบ v1.4.2)

### หน้ากรอกฟอร์มต้องรู้เส้นทางก่อนครูกดบันทึก

การส่งข้อมูลขึ้นชีตใช้วิธีที่ **อ่านผลกลับไม่ได้** ถ้ายิงไปทางที่ใช้ไม่ได้ **ข้อมูลครูจะหายเงียบ ๆ**

จึงยิงคำสั่ง `verify` เบา ๆ ตั้งแต่เปิดหน้า (ไม่ต้องใช้รหัสผ่าน ไม่คืนข้อมูลใด ๆ) เพื่อให้รู้เส้นทางที่ใช้ได้ก่อนที่ครูจะกดบันทึกจริง

## ปรับหน้าจอตอนรอ

ของเดิมกดแล้วปุ่มหน้าตาเหมือนเดิมทุกอย่าง คนกดไม่แน่ใจว่ากดติดไหม แล้วเผลอกดซ้ำ

- **ตัวหมุน** หน้าข้อความ (`.err.wait::before`) เห็นชัดว่าระบบกำลังทำงาน
- **ปุ่มเปลี่ยนข้อความ** เป็น "กำลังเชื่อมต่อ..." → "กำลังลองใหม่ (2/3)" และจางลง + ตัวชี้เป็นรูปนาฬิกา
- **ล้มแล้วปุ่มเปลี่ยนเป็น "ลองใหม่อีกครั้ง"** ให้ชัดว่าต้องกดอะไรต่อ (เดิมกลับไปเขียนว่า "เข้าสู่ระบบ" คนจึงไม่รู้ว่ากดซ้ำได้)
- ⚠️ ข้อความเดิมของปุ่มต้องจำไว้ตั้งแต่ตอนโหลดหน้า (`GATE_LABEL`) **ห้ามอ่านจากปุ่มตอนกด** ไม่งั้นจะได้ข้อความที่ถูกเปลี่ยนไปแล้วมาเป็นค่าเดิม (เจอจริงตอนทดสอบ: กรอกรหัสผิดแล้วปุ่มขึ้นว่า "ลองใหม่อีกครั้ง")

## ทดสอบแล้ว

- **ทางถอยทำงาน** — เครื่องทดสอบไม่มี `/gs` (มีแต่บน Netlify) ระบบถอยไปยิงตรงเองอัตโนมัติ ทั้งหน้ารายงานและหน้ากรอกฟอร์ม
- ล้มทุกครั้ง → ข้อความบอกสาเหตุพร้อมจำนวนครั้ง + ปุ่มเป็น "ลองใหม่อีกครั้ง"
- รหัสผ่านผิด → ยิงครั้งเดียว ปุ่มกลับเป็น "เข้าสู่ระบบ" ถูกต้อง
- สลับไปมาระหว่างรหัสผิด/เน็ตล้ม/รหัสผิด → ข้อความปุ่มถูกต้องทุกครั้ง

## ต้องเช็คหลัง deploy

1. เปิดหน้ารายงาน ดูว่าขึ้น **เวอร์ชัน 1.5.0** แล้ว
2. เข้าใน **Edge / Safari** ที่เคยพัง — ควรเข้าได้ตั้งแต่ครั้งแรก
3. ถ้ายังไม่ได้ ให้ดูในคอนโซลว่ายังมี `script.google.com` โผล่มาไหม
   - **ไม่มีแล้ว** = ทางผ่านทำงาน ปัญหาอยู่ที่อื่น
   - **ยังมี** = ทางผ่านใช้ไม่ได้ ระบบถอยไปทางเดิม ต้องดูว่า Netlify อ่าน `_redirects` หรือยัง
