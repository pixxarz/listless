## ทำไมยังไม่จบใน v1.4.2

v1.4.2 ใส่การลองใหม่ 3 ครั้งต่อการกด 1 ที แต่วัดผลจริงบนเครื่องผู้ใช้แล้วยังใช้งานไม่ได้

- **Safari (iPhone)** — กด 7 ครั้ง เข้าได้ 2 ครั้ง (ทั้งที่แต่ละครั้งลองให้ 3 รอบแล้ว = ยิงไป 21 ครั้ง สำเร็จ 2)
- **Edge** — ต้องกดราว 8 ครั้งถึงเข้าได้

โอกาสสำเร็จต่อการยิง 1 ครั้งเหลือราว **10%** เท่านั้น

**สรุป: การลองใหม่เป็นการกลบอาการ ไม่ได้แก้ต้นเหตุ** ต้นเหตุคือเบราว์เซอร์แปลชื่อ `script.google.com` เป็นที่อยู่ไม่ได้ (`ERR_NAME_NOT_RESOLVED`) เพราะ Edge/Safari ใช้ตัวแปลชื่อโดเมนของตัวเอง ไม่ใช่ของเครื่อง

## ทางแก้ที่ต้นเหตุ — ทางผ่าน (proxy)

**ทำให้เบราว์เซอร์ไม่ต้องแปลชื่อของ Google อีกเลย**

เว็บเรียก `/gs` ซึ่งเป็นชื่อเว็บตัวเอง (เปิดได้อยู่แล้วแน่นอน) แล้ว Netlify ส่งต่อคำขอไปให้ Apps Script

```
/gs   https://script.google.com/macros/s/.../exec   200
```

🚨 **ต้องเป็นรหัส 200 เท่านั้น** ถ้าใช้ 301/302 เบราว์เซอร์จะวิ่งไป `script.google.com` เองอยู่ดี แล้วเจอปัญหาเดิม

### ทางถอยอัตโนมัติ — สำคัญที่สุดของงานรอบนี้

ไม่ใช่แค่เปลี่ยนที่อยู่แล้วจบ เพราะถ้าทางผ่านใช้ไม่ได้ (เช่นเปิดไฟล์จากเครื่องตรง ๆ ที่ไม่มี Netlify) จะพังทั้งระบบ

- ตั้งต้นใช้ `/gs` เสมอ
- ล้มด้วยความผิดพลาดของเครือข่าย → `markRouteFailed()` สลับไปยิง `script.google.com` ตรง ๆ **แล้วลองใหม่ทันที ไม่นับเป็นการลองซ้ำ** (เป็นการเปลี่ยนเส้นทาง ไม่ใช่เน็ตสะดุด)
- จำไว้ว่าทางไหนใช้ได้ ครั้งต่อไปใช้ทางนั้นเลย

**จึงไม่มีทางแย่กว่าเดิม** กรณีแย่สุดคือเท่าเดิม (ยิงตรง + ลองใหม่ 3 ครั้งแบบ v1.4.2)

### หน้ากรอกฟอร์มต้องรู้เส้นทางก่อนครูกดบันทึก

การส่งข้อมูลขึ้นชีตใช้วิธีที่ **อ่านผลกลับไม่ได้** ถ้ายิงไปทางที่ใช้ไม่ได้ **ข้อมูลครูจะหายเงียบ ๆ**

จึงยิงคำสั่ง `verify` เบา ๆ ตั้งแต่เปิดหน้า (ไม่ต้องใช้รหัสผ่าน ไม่คืนข้อมูลใด ๆ) เพื่อให้รู้เส้นทางที่ใช้ได้ก่อนที่ครูจะกดบันทึกจริง

## ปรับหน้าจอตอนรอ

ของเดิมกดแล้วปุ่มหน้าตาเหมือนเดิมทุกอย่าง คนกดไม่แน่ใจว่ากดติดไหม แล้วเผลอกดซ้ำ

- **ตัวหมุน** หน้าข้อความ (`.err.wait::before`) เห็นชัดว่าระบบกำลังทำงาน
- **ปุ่มเปลี่ยนข้อความ** เป็น "กำลังเชื่อมต่อ..." → "กำลังลองใหม่ (2/3)" และจางลง + ตัวชี้เป็นรูปนาฬิกา
- **ล้มแล้วปุ่มเปลี่ยนเป็น "ลองใหม่อีกครั้ง"** ให้ชัดว่าต้องกดอะไรต่อ (เดิมกลับไปเขียนว่า "เข้าสู่ระบบ" คนจึงไม่รู้ว่ากดซ้ำได้)
- ⚠️ ข้อความเดิมของปุ่มต้องจำไว้ตั้งแต่ตอนโหลดหน้า (`GATE_LABEL`) **ห้ามอ่านจากปุ่มตอนกด** ไม่งั้นจะได้ข้อความที่ถูกเปลี่ยนไปแล้วมาเป็นค่าเดิม (เจอจริงตอนทดสอบ: กรอกรหัสผิดแล้วปุ่มขึ้นว่า "ลองใหม่อีกครั้ง")

## ทดสอบแล้ว

- **ทางถอยทำงาน** — เครื่องทดสอบไม่มี `/gs` (มีแต่บน Netlify) ระบบถอยไปยิงตรงเองอัตโนมัติ ทั้งหน้ารายงานและหน้ากรอกฟอร์ม
- ล้มทุกครั้ง → ข้อความบอกสาเหตุพร้อมจำนวนครั้ง + ปุ่มเป็น "ลองใหม่อีกครั้ง"

- สลับไปมาระหว่างรหัสผิด/เน็ตล้ม/รหัสผิด → ข้อความปุ่มถูกต้องทุกครั้ง

## ผลจริงหลัง deploy — ทางผ่านใช้ไม่ได้ ถอดออกใน v1.5.1

ทดสอบบนเว็บจริงแล้วพบว่า **Netlify ส่งต่อคำขอไปถึง Google ได้จริง แต่ Google ตอบ 400 Bad Request ทุกครั้ง**
(ทดสอบซ้ำโดยให้เซิร์ฟเวอร์ยิงเองก็ได้ 400 เหมือนกัน)

🚨 **Apps Script ยอมคุยกับเบราว์เซอร์จริงเท่านั้น ไม่ยอมให้ใครเป็นตัวกลางส่งต่อ**
ห้ามเสียเวลาลองซ้ำ ไม่ว่าจะเป็น Netlify redirect · Netlify Function · หรือ proxy ตัวอื่น

จึงถอดทางผ่านออกใน v1.5.1 เพราะระบบต้องเสียเวลาลองทางที่ตายแล้วก่อนทุกครั้ง แล้วค่อยถอย — เป็นภาระเปล่า ๆ
**ของที่เก็บไว้ทั้งหมด:** ระบบลองใหม่ · ข้อความบอกสาเหตุ · ตัวหมุน · ปุ่ม "ลองใหม่อีกครั้ง" · ระบบลองใหม่ในหน้ากรอกฟอร์ม

## v1.5.1 — เพิ่มจำนวนครั้งที่ลองใหม่ 3 → 6

วัดจากผู้ใช้จริงบน v1.5.0 (ลองใหม่ 3 ครั้ง): **กด 5 ครั้ง เข้าได้ 4** = 80%
คำนวณย้อนได้ว่าโอกาสสำเร็จต่อการยิง 1 ครั้งอยู่ราว **40%**

| ลองใหม่ | โอกาสเข้าได้ต่อการกด 1 ที |
|---|---|
| 3 ครั้ง | 80% |
| 6 ครั้ง | **~95%** |

เว้นระยะเพิ่มขึ้นแต่**ตัดเพดานที่ 4 วินาที** ไม่งั้นครั้งท้าย ๆ จะรอถึง 32 วินาที

**เหตุผลที่เลือกทางนี้:** อาการเป็นแบบสุ่ม ไม่ใช่พังถาวร การเพิ่มโอกาสจึงได้ผลโดย**ไม่ต้องรู้ต้นเหตุที่แน่ชัด**
และครูไม่ต้องตั้งค่าอะไรในเครื่องเลย

## สาเหตุที่ยังหาไม่เจอ (จดไว้กันไล่ซ้ำ)

ตรวจแล้วว่า **ไม่ใช่** ทุกข้อต่อไปนี้ — อย่าเสียเวลาไล่ซ้ำ
- ไม่ใช่ DNS ที่ปลอดภัยของ Edge (ตรวจแล้วปิดอยู่ และถูกล็อกโดยองค์กร แก้เองไม่ได้)
- ไม่ใช่ VPN / Edge Secure Network (ปิดอยู่)
- ไม่ใช่สิทธิ์หรือนโยบายของ Google (โหมดไม่ระบุตัวตนก็เข้าได้)
- ไม่ใช่ตัวบล็อกโฆษณาหรือส่วนขยาย (ผู้ใช้ไม่ได้ติดตั้ง)
- ไม่ใช่ข้อมูลค้างในเครื่อง (โหมดไม่ระบุตัวตนก็เป็น)

**ที่รู้แน่:** Edge/Safari แปลชื่อ `script.google.com` ไม่ได้เป็นครั้งคราว (`ERR_NAME_NOT_RESOLVED`)
ส่วน Chrome บนเครื่องเดียวกันไม่เคยเป็น — สาเหตุที่ลึกกว่านั้นยังตอบไม่ได้

## 🔴 สาเหตุจริงที่หาเจอทีหลัง — ไม่ใช่เน็ตหรือ DNS

หลังจาก deploy v1.5.1 ได้ดู **แท็บ Network จากเครื่องที่พังจริง** แล้วเจอคำตอบ

```
exec?key=...&callback=__cb1_...   302 → 404   ❌
exec?key=...&callback=__cb2_...   302 → 404   ❌
exec?key=...&callback=__cb3_...   302 → 404   ❌
```

**คำขอไปถึง Google ได้ปกติ ตอบกลับเร็ว 300-500 มิลลิวินาที แต่ Google ตอบว่า 404 ไม่พบ**
ไม่ใช่เน็ตช้า ไม่ใช่แปลชื่อโดเมนไม่ได้ ไม่ใช่ถูกบล็อก

### ทดสอบชี้ขาด — เครื่องเดียวกัน ต่างแค่ล็อกอิน Google

| โหมด | ผล |
|---|---|
| เบราว์เซอร์ปกติ (ล็อกอิน Google หลายบัญชีค้างไว้) | 302 → **404** ❌ |
| โหมดส่วนตัว InPrivate (ไม่ล็อกอิน) | 302 → **200** ✅ เข้าได้ปกติ |

🚨 **Apps Script ตอบ 404 เมื่อเบราว์เซอร์ล็อกอิน Google หลายบัญชีพร้อมกัน**
ทั้งที่ deploy ตั้งเป็น "ทุกคน" แล้ว และต่อให้คนที่ล็อกอินอยู่จะเป็นเจ้าของสคริปต์เองก็ตาม
(Google routing ไปยัง account context ผิดตัว — เป็นข้อจำกัดของ Apps Script ที่แก้ในโค้ดเว็บไม่ได้)

**ทางแก้สำหรับผู้ใช้ที่เจอปัญหา**
1. ออกจากบัญชี Google ในเบราว์เซอร์นั้นให้เหลือ **บัญชีเดียว** แล้วปิดเปิดเบราว์เซอร์ใหม่
2. หรือเปิดหน้ารายงานในโหมดส่วนตัว (`Ctrl+Shift+N`)

### หลังบ้านช้าจริงด้วย

จากแท็บ Network เดียวกัน บางคำขอใช้เวลา **10-29 วินาที** จึงตอบกลับ
timeout เดิมที่ 20 วินาทีตัดทิ้งไปหลายคำขอทั้งที่กำลังจะสำเร็จ — การยืดเป็น 45 วินาทีจึงจำเป็นจริง

### 🔴 บทเรียนที่แพงที่สุดของงานนี้

ไล่ผิดทาง **6 รอบ** ก่อนจะเจอ (เน็ตช้า · ตัวบล็อกโฆษณา/VPN · ข้อมูลค้างในเครื่อง · สิทธิ์ Google · นโยบาย Workspace ของโรงเรียน · DNS ของ Edge)
**ทั้งหมดจบใน 1 นาทีเมื่อได้ดู Network tab ของเครื่องที่พังจริง**

**กฎสำหรับคราวหน้า: บั๊กที่เกิดกับเครื่องคนอื่น ให้ขอ F12 → Network + Console จากเครื่องนั้นตั้งแต่แรก ห้ามเดาสาเหตุก่อน**
และ **Console อย่างเดียวไม่พอ** — เคสนี้ Console ขึ้นว่า "No errors" เพราะคำขอสำเร็จ (แค่ได้ 404 กลับมา) ต้องดู Network ถึงจะเห็น

## ต้องเช็คหลัง deploy

1. เปิดหน้ารายงาน ดูว่าขึ้น **เวอร์ชัน 1.5.0** แล้ว
2. เข้าใน **Edge / Safari** ที่เคยพัง — ควรเข้าได้ตั้งแต่ครั้งแรก
3. ถ้ายังไม่ได้ ให้ดูในคอนโซลว่ายังมี `script.google.com` โผล่มาไหม
   - **ไม่มีแล้ว** = ทางผ่านทำงาน ปัญหาอยู่ที่อื่น
   - **ยังมี** = ทางผ่านใช้ไม่ได้ ระบบถอยไปทางเดิม ต้องดูว่า Netlify อ่าน `_redirects` หรือยัง
