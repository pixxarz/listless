## อาการ

ผู้ใช้บางคนเข้าหน้ารายงานไม่ได้เลย ขึ้นว่า **"เชื่อมต่อไม่สำเร็จ ลองใหม่อีกครั้ง"** ทุกครั้งที่กดเข้าสู่ระบบ

- **Chrome เข้าได้** (แม้โหมดไม่ระบุตัวตน)
- **Edge เข้าไม่ได้** · **Safari บน iPhone เข้าไม่ได้**
- เกิดกับ **เครื่องเดียวกัน เน็ตเดียวกัน ลิงก์เดียวกัน เวลาเดียวกัน** ต่างแค่เบราว์เซอร์
- หน้ากรอกฟอร์มของครูยังใช้งานได้ปกติตลอด

## 🚨 ทางที่หลงไปก่อน และเหตุผลที่ตกไป

ไล่ผิดทางหลายรอบก่อนจะเจอของจริง จดไว้กันคนหลังเสียเวลาซ้ำ

| สมมติฐาน | ตกไปเพราะ |
|---|---|
| เน็ตช้า / ข้อมูลใหญ่เกิน | เป็นเฉพาะบางเบราว์เซอร์บนเครื่องเดียวกัน |
| ตัวบล็อกโฆษณา / VPN | ผู้ใช้ไม่ได้เปิด และไม่มีส่วนขยายเลย |
| ข้อมูลค้างใน `localStorage` | โหมดไม่ระบุตัวตน (ไม่มีข้อมูลเก่า) ก็ยังพัง |
| **สิทธิ์ของ Apps Script (ต้องล็อกอิน Google)** | **เข้าใจผิดเอง** — เอาลิงก์ไปเปิดตรง ๆ ในเบราว์เซอร์แล้วเห็น "ไม่พบเพจ" เลยฟันธงว่าหลังบ้านพัง แต่**เว็บไม่ได้เรียกแบบนั้น** การเปิดตรง ๆ ไม่ผ่านไม่ได้แปลว่าเว็บเรียกไม่ได้ · พิสูจน์ตกไปเมื่อเปิดหน้ารายงานในโหมดไม่ระบุตัวตนแล้วเข้าได้ปกติ |
| นโยบาย Google Workspace ของโรงเรียนบล็อก | ตกไปด้วยเหตุผลเดียวกัน |

**บทเรียน: อย่าใช้ "เปิด URL ตรง ๆ ในเบราว์เซอร์" เป็นหลักฐานว่าหลังบ้านพัง** — Apps Script ปฏิบัติกับการเปิดตรง ๆ คนละแบบกับการเรียกจากหน้าเว็บ

## สาเหตุจริง (จากคอนโซลของเครื่องที่พัง)

```
net::ERR_NAME_NOT_RESOLVED    script.google.com     ← ครั้งที่ 1
net::ERR_NETWORK_CHANGED      script.google.com     ← ครั้งที่ 2
Uncaught ReferenceError: __cb6_1786525094704 is not defined   ← ครั้งที่ 3
```

บรรทัดที่ 3 คือกุญแจ — **คำขอที่ 3 สำเร็จ ข้อมูลกลับมาถึงเบราว์เซอร์จริง** แต่เว็บ**เลิกรอไปแล้ว** ตัวรับข้อมูลถูกลบทิ้ง พอสคริปต์เรียกหาจึงไม่เจอ

แปลว่า
1. เน็ต/ตัวแปลชื่อโดเมนของเบราว์เซอร์นั้นสะดุดเป็นครั้งคราว (Edge กับ Safari ใช้ DNS คนละชุดกับ Chrome จึงสะดุดบ่อยกว่า)
2. **แต่ที่ทำให้กลายเป็น "พังถาวร" คือตัวเว็บเอง** — รอแค่ 20 วินาทีแล้วยอมแพ้ และ**ไม่ลองใหม่ให้เลยสักครั้ง**

ปัญหาที่แท้จริงจึงไม่ใช่ "เข้าไม่ได้" แต่คือ **"ต้องลองอีกที แต่เว็บไม่ยอมลอง"**

## สิ่งที่แก้

### `js/report.js`
- `jsonp()` กลายเป็นตัวห่อที่ **ลองใหม่อัตโนมัติ** เรียก `once()` ซ้ำได้สูงสุด 3 ครั้ง เว้นระยะ 1 แล้ว 2 วินาที
- **ลองใหม่เฉพาะความผิดพลาดของเครือข่าย** (`network` / `timeout`) เท่านั้น — รหัสผ่านผิดยิงครั้งเดียวจบ ไม่รบกวนเซิร์ฟเวอร์เปล่า ๆ
- ยืดเวลารอต่อครั้งจาก 20 เป็น **45 วินาที** (ชีตโตขึ้น หลังบ้านอ่าน 2 แผ่นต่อคำขอ 20 วินาทีไม่พออีกแล้ว)
- ตอนหมดเวลา เปลี่ยนจากลบตัวรับข้อมูลทิ้ง เป็น**แทนที่ด้วยตัวเปล่า** — ข้อมูลที่มาช้าจะถูกรับแล้วทิ้งเงียบ ๆ ไม่โผล่เป็น error ในคอนโซลอีก
- `netErrorText()` แยกข้อความตามสาเหตุจริง พร้อมบอกว่าลองไปกี่ครั้งแล้ว
- หน้าใส่รหัสผ่านแสดงสถานะระหว่างรอ (**"เครือข่ายสะดุด กำลังลองใหม่ ครั้งที่ 2 จาก 3..."** สีเทา ไม่ใช่แดง) ผู้ใช้จะได้รู้ว่าระบบยังทำงานอยู่ ไม่ใช่ค้าง

### `js/fixes.js`
- `jsonpGet()` มีทางเชื่อมต่อของตัวเองแยกจากหน้ารายงาน จึงต้องแก้ให้เหมือนกัน — ลองใหม่ 3 ครั้ง รอ 45 วินาที และรับข้อมูลที่มาช้าไว้เงียบ ๆ เช่นกัน
- **ถ้าเพิ่มทางเชื่อมต่อใหม่ที่ไหนอีกในอนาคต ต้องใส่การลองใหม่ให้ครบทุกที่** ไม่งั้นจุดนั้นจะพังแบบเดิม

### `css/report.css`
- `.err.wait` สีเทาสำหรับข้อความ "กำลังลองใหม่" แยกจากข้อความผิดพลาดสีแดง
